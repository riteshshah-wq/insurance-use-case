== Overview

GoldenRay integrates with MLflow for experiment tracking and model registry. Every claims processing run and model training job logs metrics, parameters, and artifacts to MLflow.

== Step 1: Access MLflow UI

Open the MLflow UI in your browser:

[source]
----
http://10.0.0.113:30500
----

You should see the MLflow Tracking UI with experiment lists. If the `insurance-claims-processing` experiment doesn't exist yet, it will be created on the first API call.

== Step 2: Generate Tracking Data

Process several claims to generate MLflow tracking data:

[source,bash]
----
# Process all sample claims
for i in 1 2 3 4 5; do
  echo "Processing claim${i}..."
  curl -s -X POST http://localhost:8001/api/claims/process \
    -H "Content-Type: application/json" \
    -d "{\"text\": $(cat data/sample_claims/claim${i}.txt | jq -Rs .)}" | jq '{severity: .classification.severity, team: .routing.adjuster_team}'
  echo
done
----

[NOTE]
====
MLflow logging is attempted in the Flyte pipeline (`pipelines/claims_pipeline.py`). If MLflow is not reachable from the application, the pipeline continues with a fallback ID. The data is still processed correctly — MLflow tracking is observability, not a blocking dependency.
====

== Step 3: Review Metrics in MLflow

In the MLflow UI, navigate to the `insurance-claims-processing` experiment:

* **Parameters**: claim_type, severity, adjuster_team
* **Metrics**: claim_amount, confidence, priority
* **Artifacts**: extraction.json, classification.json, routing.json

=== Key Metrics to Track

[cols="1,2,2"]
|===
|Metric |What It Measures |Target

|`claim_amount` |Dollar amount of the claim |Business distribution tracking
|`confidence` |Classification confidence score |> 0.8 for production
|`priority` |Routing priority (1-5) |Distribution across teams
|`extraction_accuracy` |% of fields correctly extracted |> 0.9 for production
|`json_parse_rate` |% of LLM outputs that parse as valid JSON |> 0.95 for production
|`avg_latency_ms` |Model inference latency |< 2000ms for interactive use
|===

== Step 4: Model Training Pipeline Metrics

If you've run the training pipeline, check the `insurance-model-training` experiment:

[source,bash]
----
# List MLflow experiments
curl -s http://10.0.0.113:30500/api/2.0/mlflow/experiments/list | jq '.experiments[] | {name, experiment_id}'
----

Training metrics include:

* `final_loss`: Training loss at end of fine-tuning
* `extraction_accuracy`: Accuracy on held-out claim extraction
* `classification_accuracy`: Severity classification accuracy
* `json_parse_rate`: How often the model produces valid JSON

== Step 5: Comparing Model Performance

Use the MLflow comparison view to compare runs across different models:

1. In MLflow UI, select the experiment
2. Check multiple runs
3. Click "Compare"
4. View metric charts to identify the best-performing model

== Step 6: Setting Up Alerts (Production)

For production monitoring, configure alerts on key metrics:

[source,yaml]
----
# Example: Prometheus alerting rules for insurance API
groups:
  - name: insurance-ai
    rules:
      - alert: LowExtractionAccuracy
        expr: avg(extraction_accuracy) < 0.8
        for: 1h
        labels:
          severity: warning
        annotations:
          summary: "Claims extraction accuracy below 80%"

      - alert: HighLatency
        expr: avg(inference_latency_seconds) > 3
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Model inference latency above 3 seconds"

      - alert: ModelEndpointDown
        expr: up{job="insurance-llm"} == 0
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "Insurance LLM endpoint is down"
----

== Troubleshooting

[cols="2,3"]
|===
|Symptom |Fix

|MLflow UI not accessible at `:30500`
|Check network/VPN connectivity to `10.0.0.113`. The port may be blocked or the MLflow pod may not be running.

|No experiments visible in MLflow
|Experiments are created by the Flyte pipeline, not the REST API directly. Run `pipelines/claims_pipeline.py` if you need MLflow data.

|"Connection refused" errors in app logs mentioning MLflow
|MLflow is optional. The app continues working without it. Set `MLFLOW_TRACKING_URI` to a reachable URI or ignore the warnings.
|===
