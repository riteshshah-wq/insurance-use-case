== Overview

The customer agent uses Retrieval Augmented Generation (RAG):

[source]
----
Customer Question → Retrieve Policy Docs → Augment Prompt → LLM Answer → Response
----

Policy documents are loaded at startup from `data/sample_policies/`. The agent searches them using keyword matching (demo) or vector similarity (production with GoldenRay RAG endpoint).

== Step 1: Simple Policy Question

[source,bash]
----
curl -s -X POST http://localhost:8001/api/agent/chat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "What is my deductible for auto insurance?"
  }' | jq .
----

Expected output:
[source,json]
----
{
  "response": "Based on the auto policy document, your deductible for collision coverage is $500, and for comprehensive coverage it is $250...",
  "sources": ["auto_policy.txt"]
}
----

[NOTE]
====
With TinyLlama, responses may be basic or partially relevant. The key is that the RAG system correctly retrieves `auto_policy.txt` and includes it in the context. Larger models will produce much better answers from the same retrieved context.
====

== Step 2: Home Insurance Question

[source,bash]

  -H "Content-Type: application/json" \
  -d '{

2. Protect property from further damage
3. Document damage with photos
4. Create inventory of damaged items
5. Keep receipts for emergency repairs

== Step 4: Multi-Turn Conversation

Send a follow-up question with conversation history:

[source,bash]
----
curl -s -X POST http://localhost:8001/api/agent/chat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "What is the time limit for that conversion?",
    "conversation_history": [
      {"role": "user", "content": "Can I convert my term life policy to permanent?"},
      {"role": "assistant", "content": "Yes, you can convert your term life policy to a permanent whole life policy without evidence of insurability."}
    ]
  }' | jq .
----

Expected: The agent uses conversation context plus retrieved documents to answer that conversion is available during the first 15 years of the term or before age 65.

== How RAG Works in This Demo

[source]
----
1. Customer asks: "What is my auto deductible?"
2. RAG retriever splits query into keywords: [auto, deductible]
3. Searches all policy document chunks for matching terms
4. Finds relevant chunks in auto_policy.txt (Section 4: Collision, Section 5: Comprehensive)
5. Injects chunks into LLM prompt as context
6. LLM generates answer grounded in the actual policy text
----

=== Production RAG Improvements

For production, replace the keyword-based retrieval with:

* **GoldenRay RAG endpoint**: Vector similarity search using embeddings
* **Embedding model**: Generate embeddings for document chunks
* **Vector DB**: Store and search embeddings efficiently (Milvus, ChromaDB)
* **Reranking**: Use a cross-encoder to rerank retrieved chunks
* **Chunk optimization**: Tune chunk size, overlap, and splitting strategy

== Troubleshooting

[cols="2,3"]
|===
|Symptom |Fix

|`sources` array is empty
|The keyword retriever found no matching terms. Try a question with words that appear in the policy docs (e.g., "deductible", "coverage", "claim").

|Response says "I apologize, but I'm having trouble..."
|The LLM endpoint is unreachable. Check `uvicorn` logs for connection errors. The fallback message is by design — the app never crashes on LLM failure.

|Response doesn't match the policy documents
|TinyLlama may ignore or hallucinate over the provided context. Check the `sources` field — if the right document was retrieved, the RAG pipeline is working correctly. Better models produce better answers from the same context.

|`conversation_history` seems ignored
|Only the last 6 messages from history are included to stay within TinyLlama's context window. Keep conversations short.
|===
